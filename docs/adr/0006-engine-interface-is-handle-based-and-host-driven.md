# The engine interface is handle-based and host-driven

The engine interface (`native/engine/crates/gable-engine-api`) that the Host runtime codes against, and that both the QuickJS-NG adapter and the Gable engine implement, uses lifetime-free handles, a single `&mut dyn Engine` entry point, and a `Host` trait of default-implemented hooks. The engine never runs a job, reads a clock or loads a file on its own: the host drives it.

## Decision

- **Values are a plain enum with persistent handles.** `Value` is `Undefined | Null | Bool | Number | String | BigInt | Symbol(Handle) | Object(Handle)`. Strings and BigInts are copied out (UTF-16 units, decimal text); objects and symbols are `Handle`s: reference-counted ids into a per-engine registry. Dropping the last clone of a handle queues its slot for release, and every engine entry point reclaims queued slots. There are no Rust lifetimes on values, so the Host runtime can keep a handle in a struct, a signal or a closure without fighting the borrow checker. The cost is that a handle is a strong root until dropped; the scoped root stack of spec section 5 is an engine-internal matter, not part of the interface.
- **One trait, every method on `&mut self`.** Engines are single-threaded and own their heap, so there is no reason for interior mutability in the interface. Host functions receive `&mut dyn Engine` and may re-enter.
- **Realms are ids.** `create_realm` returns a `RealmId`; every evaluation and value operation that can run user code names the realm it runs in. Handles are engine-wide (QuickJS and the Gable engine both share one heap across realms).
- **The host supplies everything non-ECMAScript** through the `Host` trait: module resolution and loading (returning source, JSON text or bytecode), `import.meta` population, the promise-rejection tracker, `HostEnsureCanCompileStrings`, the console sink and an interrupt poll. Every method has a default so hosts implement what they use. `run_jobs` is the only way jobs run.
- **Errors are a closed enum.** `Error::Exception` carries the thrown value plus its name, message and parsed stack; `Interrupted`, `OutOfMemory`, `BytecodeMismatch` and the rest are separate variants so the host can react without inspecting JS values.
- **Bytecode is wrapped in a container** (`GBJS` magic, NUL-terminated format tag, payload). The tag names the engine and version that produced it, so a mismatch is rejected before the payload is touched. Payload format is the engine's own.
- **Host classes carry Rust data behind `Any`** with a `trace` hook reporting the JS values they hold, and a finalizer that runs as a host task after collection, never during it.
- **The conformance kit lives in the interface crate.** `conformance_tests!(factory)` expands to twenty-one `#[test]`s covering evaluation, exceptions, host functions, job draining, rejection tracking, modules (including reload under a new specifier), realms, interrupt, memory limits, host classes, bytecode round trip, script source, console, compile-strings denial, object manipulation, handle release, `DetachArrayBuffer` and promise state. The QuickJS-NG adapter passes it; the Gable engine must pass the same kit in M7.

## Considered options

Lifetime-bound values (`Value<'js>` as rquickjs does): safe and zero-cost, but the Host runtime keeps JS values in long-lived Rust structures, and a lifetime on every one of them spreads through the whole host. A scoped root stack in the interface (`with_scope(|scope| ...)`): the right internal design for the Gable engine's collector, but awkward for the host's retained tree; it stays behind the interface. Interior mutability (`&self` everywhere): invites accidental re-entrancy bugs for no benefit on a single thread. Strings as handles: saves copies but makes every string comparison an engine call; the host mostly wants Rust strings.

## Consequences

The QuickJS-NG adapter has to bridge rquickjs's lifetimes and its non-reentrant `Context::with`: it tracks nesting in a thread-local and re-derives `Ctx` from the raw context when already inside, and creates realms through the raw API when a host function asks for one. QuickJS-NG has no `HostEnsureCanCompileStrings` hook, so the adapter swaps `eval` and `Function` for throwing wrappers while the host forbids compilation, and its host functions always report `new_target` as `None`. Those are adapter limitations, recorded here so the Gable engine does not inherit them. Handles being strong roots means a host that leaks a handle leaks the object; the kit's `handles_are_released_when_dropped` test keeps the release path honest. The interface is reviewed again against the Gable engine before M2 starts, as the spec requires.

## Addendum (2026-11-08, M4): releasing module records

`Engine::release_module(realm, specifier)` forgets the module-map entry for a resolved specifier so the next import evaluates the module again and the old record is collected once unreachable. It exists because spec section 7 wants module re-loading without an engine-side hot-update primitive: HMR logic in JavaScript decides what to re-import, and importers of the old record keep their bindings until they do. The method returns `false` on engines that cannot drop records; the QuickJS-NG adapter returns `false` (QuickJS keeps every module for the life of its context), so HMR on the interim engine reloads into a fresh realm. The conformance kit observes collection through a host-class finaliser rather than `WeakRef`, so it works on both adapters and before the collections milestone.
