## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decisions (ADR 0015): ICU4X 2.4 behind the gable-js-intl seam; VM does the ECMA-402 abstract operations, the seam owns tag tokenizing/canonicalization and all locale-sensitive formatting and exposes plain Rust types only. CLDR unit/currency/number tables for 17 locales (with parent then en fallback) and numbering-system/unit/zone tables are generated by tools/gen-cldr.js and tools/gen-tables.js. Spec-shaped recovery lives in the seam: synthesized h23 hour for hour-less bags and h24, weekday width via a second formatter, two-digit year for dateStyle short, range parts recovered by aligning interval runs against the single formats with a manual join fallback, arab/arabext symbols from ar/fa, und root fill for likely subtags, JP-only h11, currency code as fallback name, PluralRules on compact/scientific operands. Per-realm FallbackSymbol. Runner flag --only-intl402 runs intl402 against baselines/gable-intl402.json; CI runs it as a separate step. Host gained default_locale() and default_time_zone() hooks.

Verification: intl402 981 passed / 0 failed (12 reasoned exclusions in exclusions/gable.txt: 8 flexible day period tests (ICU4X 2.4 has no CLDR B), DurationFormat (post-ES2025), Collator/usage-de (no German search tailoring), PluralRules plural-categories-order (no gv data), DateTimeFormat/format/numbering-system.js (expectation hard-codes U+0020 for U+202F)). Main suite 42225/42225 with 0 regressions. cargo test for gable-js-intl, gable-js-vm and gable-js-test262 green.

AC #1 left unchecked on purpose: the seam exists and the crate-owned CLDR tables are trimmed to a configured locale list, but ICU4X's own compiled data is still the crate-default set. Trimming it to application locales needs an icu4x-datagen custom baked-data crate behind the same seam; follow-up.
