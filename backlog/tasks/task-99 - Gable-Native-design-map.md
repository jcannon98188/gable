## Destination

A spec for Gable Native: a decision-complete design for a native renderer that replaces the DOM for driving desktop (Windows, macOS, Linux) and Android applications, ready for a later effort to plan and build. It covers the architecture and host, the Renderer-seam changes, the styling model, the shared template vocabulary, platform services, the dev loop, testing and packaging, and a recommended build order. No renderer code is written in this effort beyond throwaway prototypes that answer a question.

## Notes

Consult GLOSSARY.md (Renderer, Platform services, Test renderer, Host) and the Gable v0 design map, especially its Renderer abstraction decision; the current seam is `packages/core/src/renderer.ts`, with the DOM implementation in `packages/renderer-dom`. Decided: the host is Rust and Gable owns its JavaScript engine (in Rust, behind an engine interface; an adopted engine such as QuickJS-NG runs in the interim). The implementation of the engine is a later effort. Working direction: an own-drawn renderer (Gable runs its own layout and GPU rendering on every platform), to be validated or overturned by the first tickets. Target apps are UI-heavy (forms, lists, text, dialogs, scrolling, IME, accessibility); game-like drawing is not a v1 goal, but the canvas 2D element is in v1. Template vocabulary direction: a shared subset with the DOM renderer plus renderer-specific extras. macOS standing constraint: the author cannot test on a Mac, so every stack choice must be cross-platform or have a macOS implementation, macOS-specific behaviour (menu bar, Cmd shortcuts, IME, Retina scaling, Metal, code signing and notarization) is designed in from the start, and verification relies on CI macOS runners. The no-framework-compiler rule from v0 still holds. Prefer Node.js scripts over Python for any scripting.

## Decisions so far

- [Own-drawn UI stacks across Windows, macOS, Linux and Android](backlog/tasks/task-99.1%20-%20Own-drawn-UI-stacks-across-Windows-macOS-Linux-and-Android.md): Skia and Vello are 2D renderers, Parley and AccessKit are building blocks, Slint is a stable toolkit but GPLv3 or commercial with its own model, the Flutter embedder runs Dart. Findings on branch `research/own-drawn-ui-stacks`.
- [Embeddable JS engines for desktop and Android](backlog/tasks/task-99.2%20-%20Embeddable-JS-engines-for-desktop-and-Android.md): V8 has no Android prebuilt and is large; QuickJS is tiny with near-full ES2025 but no inspector; Hermes lacks an ES module loader; JSC is macOS-only in practice; no engine has an HMR API. Findings on branch `research/embeddable-js-engines`.
- [Text shaping, layout, rendering and input across the four platforms](backlog/tasks/task-99.3%20-%20Text-shaping-layout-rendering-and-input-across-the-four-platforms.md): HarfRust shaping with Parley and Fontique as the most complete reusable stack; every platform needs its own IME bridge; macOS clipboard unverified. Findings on branch `research/native-text-and-input`.
- [Accessibility bridging across the four platforms](backlog/tasks/task-99.4%20-%20Accessibility-bridging-across-the-four-platforms.md): AccessKit has adapters for all four platforms but is pre-1.0 with no rich text and weak announce support; direct adapters are the alternative. Findings on branch `research/native-accessibility`.
- [Layout engines, windowing and the app shell](backlog/tasks/task-99.5%20-%20Layout-engines-windowing-and-the-app-shell.md): Taffy covers block, flex and grid (scrolling and hit testing are ours); winit and SDL3 cover all four platforms, winit lacks menus (muda) and has unclear Android IME. Findings on branch `research/native-layout-and-shell`.
- [Architecture and host language](backlog/tasks/task-99.6%20-%20Architecture-and-host-language.md): Rust host; Skia behind a display-list boundary with Parley, Taffy and AccessKit (the rendering choice is superseded by the renderer hybrid decision); winit plus muda on desktop and GameActivity on Android; JS thread plus main UI thread with batched ops and a retained Rust tree; prebuilt host runtime plus app bundle; Gable owns its JS engine in Rust behind an engine interface, with an adopted interim engine until a test262 gate; own the seams, adopt commodity layers.
- [Engine design prior art and test262 mechanics](backlog/tasks/task-99.10%20-%20Engine-design-prior-art-and-test262-mechanics.md): Rust engines (Boa, Nova, Brimstone) use bytecode VMs with shapes and mark-sweep or compacting GC, none has an inspector or HMR API; test262 has no edition field, so an ES2025 gate needs a pinned commit plus feature lists. Findings on branch `research/js-engine-design-and-test262`.
- [Renderer seam changes for a non-DOM renderer](backlog/tasks/task-99.7%20-%20Renderer-seam-changes-for-a-non-DOM-renderer.md): write ops unchanged but applied by the end of the flush (amends v0 "all synchronous"); reads move to new Geometry, FrameScheduler and MediaQuery Tokens; primitives-only property values on native; DOM-compatible events with blocking dispatch only for cancelable ones; remove is terminal and releases the subtree; other optional ops keep their signatures.
- [Rust CSS style engines and Tailwind v4 feature inventory](backlog/tasks/task-99.14%20-%20Rust-CSS-style-engines-and-Tailwind-v4-feature-inventory.md): Stylo is the only browser-grade Rust style engine (MPL-2.0, Python at build time) and Blitz pairs it with Taffy and Parley; selectors and cssparser give matching only; Tailwind v4 output relies on @layer, @property, @supports, color-mix, oklch, :where and :has. Findings on branch `research/rust-css-style-engines`.
- [Styling model](backlog/tasks/task-99.8%20-%20Styling-model.md): CSS subset with loud dev-time diagnostics; flex, grid and block via Taffy, tables lowered onto grid, sticky and fixed positioning; Tailwind v4 selectors and at-rules; ::before and ::after as generated boxes; filters, backdrop-filter (blur and colour functions) and single-element 3D transforms in the first version, preserve-3d later; attribute-token scoping unchanged; adopt Stylo behind a style-system boundary, to be verified in the prototype.
- [Gable JS engine design](backlog/tasks/task-99.11%20-%20Gable-JS-engine-design.md): full ES2025 plus Annex B on ICU4X Intl; register and accumulator bytecode with shapes and inline caches, no JIT, serializable bytecode; precise non-moving mark-sweep with incremental slices between flushes; a host-driven engine interface; WinterCG globals but no window or document by default; no engine-level HMR primitive; debugger interface with a CDP adapter; a pinned test262 gate with a switch-over rule from the interim engine.
- [Shared template vocabulary](backlog/tasks/task-99.9%20-%20Shared-template-vocabulary.md): native uses HTML tag names with documented native semantics and no new primitives; v1 set covers structure, tables, controls, img, picture, inline svg (usvg subset), video, audio, track, source and canvas; unsupported tags error clearly; per-renderer element maps for the language service with a shared-subset rule; no native-only tags, hosts register hyphenated extras.
- [Platform services for Gable Native](backlog/tasks/task-99.12%20-%20Platform-services-for-Gable-Native.md): in-memory Location and History with back and deep links, AccessKit-backed LiveAnnouncer and FocusManager, new Storage Token; v1 native Tokens WindowManager, Menus, Clipboard, Dialogs, Opener and Lifecycle, always provided with isSupported; multi-window designed in (window ids, a per-window injector, global handles, Android in-window fallback) with a single window first; macOS menu bar, Mod key and quit rules; Android back and lifecycle.
- [Media and canvas design for Gable Native](backlog/tasks/task-99.17%20-%20Media-and-canvas-design-for-Gable-Native.md): element facades for methods; platform media decoders behind a MediaBackend seam with a shared HTMLMediaElement state machine, external-image video frames (CPU upload first), Gable-parsed WebVTT, no DRM; canvas 2D as a JS-thread context recording for UI-thread replay into a GPU-first Skia surface with a raster fallback and blocking readback; WebGL and WebGPU post-v1.
- [Media playback on the four platforms](backlog/tasks/task-99.15%20-%20Media-playback-on-the-four-platforms.md): only Media Foundation mirrors the HTMLMediaElement state machine; Android has documented zero-copy frames and Media3; no mature pure-Rust H.264 High, HEVC or VP9 decoder; FFmpeg is LGPL only if built and linked carefully, patents fall on the distributor. Findings on branch `research/native-media-playback`.
- [Canvas 2D on Skia](backlog/tasks/task-99.16%20-%20Canvas-2D-on-Skia.md): Skia save and restore keep only matrix and clip so the context keeps its own state stack; filters, shadows and some blend modes need extra work; async readback exists only on Ganesh; skia-canvas and Servo record and replay on a render thread. Findings on branch `research/native-canvas-2d`.
- [Dev loop for Gable Native: HMR and debugging](backlog/tasks/task-99.13%20-%20Dev-loop-for-Gable-Native-HMR-and-debugging.md): a prebuilt dev host loads modules from the Vite dev server with its own Vite HMR client and a native target in @gable/vite; adb reverse on Android; core HMR unchanged with realm-level reload into the same window; host-drawn error overlay; CDP debugging from the Gable engine (none for the interim engine); devtools protocol over a local WebSocket with a hosted panel; five host requirements for a later Designer preview.
- [Vello and wgpu against Gable Native's rendering requirements](backlog/tasks/task-99.18%20-%20Vello-and-wgpu-against-Gable-Native's-rendering-requirements.md): Vello lacks filters beyond blur, backdrop-filter, perspective transforms, masks and some blends, damage tracking and LCD text, and compute Vello needs compute shaders; vello_gpu is still moving between releases; Skia could share a wgpu device through an experimental Graphite path. Findings on branch `research/vello-wgpu-rendering`; the user's contingency is to go hybrid, which reopens the renderer decision.
- [WebRender and other display-list renderers as the owned compositor](backlog/tasks/task-99.23%20-%20WebRender-and-other-display-list-renderers-as-the-owned-compositor.md): WebRender has every committed feature and built-in damage but is GL 3.2/GLES 3.0 only (no wgpu backend, deprecated OpenGL on macOS, platform glyph rasterizers, MPL-2.0); the closest design references for our boundary are Chromium cc/viz and Impeller's display list. Research on branch `research/webrender-display-list-renderers`.
- [Display-list boundary for Gable Native](backlog/tasks/task-99.21%20-%20Display-list-boundary-for-Gable-Native.md): flat item list over transform/scroll, clip and effect trees plus one hit-test tree (also feeds AccessKit); immutable snapshot built on the UI thread; resources by id and generation; glyph-run items; damage diffed by the painter; canonical serialization for goldens; canvas and video as leaf resource items.
- [Prototype spike and checkpoint for the owned renderer stack](backlog/tasks/task-99.22%20-%20Prototype-spike-and-checkpoint-for-the-owned-renderer-stack.md): checkpoint passed, continue with the owned hybrid renderer (Skia not adopted). Desktop blur, backdrop, perspective picking, masks, blends and the path seam pass; Android Vulkan works; open: macOS Metal not yet run (follow-up ticket); Stylo builds but needs Python on PATH. Branch `prototype/native-renderer-spike`.
- [Find the Android GLES 3.0 black screen in the renderer spike](backlog/tasks/task-99.24%20-%20Find-the-Android-GLES-3.0-black-screen-in-the-renderer-spike.md): cause was a vertex shader indexing a function-local array by vertex index, which SwiftShader ES 3.0 draws as nothing; fixed with arithmetic selects and confirmed on SwiftShader. Ship-gate constraint: no dynamic indexing of local arrays in GLES 3.0 vertex shaders; validate GLES on real Mali and Adreno. Scratch emulator kept as `gable-spike-api-37`.
- [Testing and conformance strategy for Gable Native](backlog/tasks/task-99.19%20-%20Testing-and-conformance-strategy-for-Gable-Native.md): eight blocking layers, a headless test host with a TestApi runner and a test-only tree API, software-rasterized goldens plus a GPU smoke suite, differential layout tests against the DOM renderer in Chromium, accessibility snapshots, a CI matrix with an Android emulator, a hosted Mac session before releases, and baseline performance gates.
- [Renderer hybrid: owned wgpu UI renderer and path engine](backlog/tasks/task-99.20%20-%20Renderer-hybrid-owned-wgpu-UI-renderer-and-path-engine.md): v1 ships an owned hybrid renderer on wgpu (compositor, UI primitives, damage and glyph-atlas text owned; vello_gpu and vello_cpu adopted for path rasterization behind a seam), superseding Skia-first; Skia stays a fallback if the prototype checkpoint fails; canvas records a Gable-owned op buffer; Vulkan, Metal or D3D12 then GLES 3.0 then CPU; six ship gates; recorded in ADR 0005.

## Not yet specified

- Build, packaging and the Android toolchain, plus macOS signing and notarization (Stylo needs Python on PATH at build time; winit 0.31 beta on Android has no IME events, so text input uses android-activity GameTextInput).
- WebGPU and WebGL for canvas (post-v1; context names reserved), now on the shared wgpu device.
- An optional, opt-in DOM-compat package for browser-only libraries (a small DOM subset over the renderer, never on by default).
- The shape of the later gable-ui and Designer ports, as requirements on the renderer only.

## Out of scope

- iOS (initial implementation).
- Web or WASM output of the native renderer.
- Porting the Designer to preview native apps.
- Porting gable-ui, the editor and the other packages (the spec notes what they will need from the renderer).
